# NutriAI — Android + FastAPI (Stage 9: стабилизация и валидация ИИ)

NutriAI — прототип Android-приложения для дневника питания с анализом фотографии через облачный ИИ. В этой версии Android-клиент уже отправляет фотографию на FastAPI, показывает результат распознавания, позволяет исправить ингредиенты/массу/КБЖУ и сохраняет пересчитанный приём пищи в локальную базу Room.

> Важно: это исходный проект, не готовый APK. В текущей среде нет Android SDK/Gradle, поэтому здесь не удалось собрать и запустить приложение на устройстве. Код необходимо собрать и проверить в Android Studio.

## Что реализовано

### Добавлено на этапе 3
- Экран подбора рецептов по введённым продуктам.
- Генерация меню на 7 дней с примерным КБЖУ и списком дополнительных покупок.
- Встроенный стартовый каталог из 20 продуктов с поиском по `GET /products`; каталог можно открыть из экрана рецептов.
- Человекочитаемый вывод рецептов и меню в приложении.

### Android
- Kotlin + Jetpack Compose, тёмный интерфейс.
- Локальный дневник Room: калории, белки, жиры, углеводы, масса и время.
- Ручное добавление продукта с расчётом по значениям на 100 г.
- Фото еды: камера **и** галерея.
- Сжатие фото до отправки, чтобы уменьшить размер загрузки.
- Настройка URL FastAPI через кнопку шестерёнки.
- Отправка изображения в `POST /analyze-food`.
- Экран проверки ответа ИИ: редактирование названия, ингредиентов, массы и КБЖУ на 100 г.
- Автоматический пересчёт итоговых калорий и макронутриентов при редактировании.
- Сохранение проверенного результата в дневнике.
- Ошибки сети и лимитов сервера отображаются пользователю.

### Backend
- FastAPI: `GET /health`, `POST /analyze-food`, `GET /products`, `POST /recipes/suggest` и `POST /menu/week`.
- Вызов Gemini API через сервер; API-ключ не хранится в APK.
- Проверка типа и размера изображения.
- Обработка недоступности API, неправильного ключа и лимитов.
- Модель по умолчанию: `gemini-3.8-flash` (можно заменить через переменную окружения).

## 1. Запустить сервер на компьютере

Установи Python 3.11+ и выполни в терминале из папки `backend`:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:GEMINI_API_KEY="ТВОЙ_API_КЛЮЧ"
$env:GEMINI_MODEL="gemini-3.8-flash"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
export GEMINI_API_KEY="ТВОЙ_API_КЛЮЧ"
export GEMINI_MODEL="gemini-3.8-flash"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Ключ можно получить в Google AI Studio: https://aistudio.google.com/app/apikey . Никому не отправляй его и не вставляй в Kotlin-код или APK.

Проверь работу сервера на компьютере: открой `http://127.0.0.1:8000/health`. В ответе ожидается JSON со статусом `ok` и `ai_configured: true`.

## 2. Подключить Android-приложение к серверу

1. Установи Android Studio и Android SDK Platform 35.
2. Открой папку `android` в Android Studio.
3. Дождись Gradle Sync и запусти приложение на телефоне или эмуляторе.
4. Компьютер и Huawei nova Y91 должны быть подключены к одной Wi-Fi сети.
5. Узнай локальный IPv4-адрес компьютера. В Windows можно выполнить `ipconfig` и найти IPv4-адрес активного Wi-Fi адаптера.
6. В NutriAI нажми ⚙ и укажи адрес, например `http://192.168.1.10:8000` (подставь свой IP).
7. Разреши входящие подключения к порту 8000 в брандмауэре Windows, если он блокирует запросы.
8. Нажми «Камера» или «Галерея», выбери еду, дождись ответа и проверь результат перед сохранением.

Для Android-эмулятора обычно используется адрес `http://10.0.2.2:8000`. На физическом телефоне `10.0.2.2` не подходит — нужен адрес компьютера или публичный HTTPS-адрес сервера.

Примечание: приложение разрешает HTTP для локальной разработки. Для размещённого в интернете сервера используй HTTPS.

## 3. Собрать APK

В Android Studio выбери **Build → Build APK(s)**. После успешной сборки Android Studio покажет путь к APK. Перед установкой на основной телефон сначала проверь сборку и распознавание на тестовом запуске.

## Ограничения текущей версии

- API должен быть запущен на компьютере/сервере; сейчас он не размещён публично автоматически.
- Бесплатный тариф Gemini зависит от региона, модели и текущих лимитов; он не гарантирует неограниченные запросы. Для бесплатного тарифа Google может использовать отправленный контент для улучшения продуктов — не отправляй фотографии с личными/чувствительными данными.
- Распознавание веса по фотографии остаётся оценкой. Проверяй массу и состав.
- Расчёт КБЖУ в этой версии масштабирует значения, предложенные ИИ; полноценный поиск по независимой базе пищевой ценности и штрихкоды ещё предстоит добавить.
- Профиль/персональная норма, журнал веса, экспорт/импорт резервной копии и сканер штрихкодов ещё предстоит реализовать. Каталог продуктов пока небольшой и не заменяет проверку этикетки.

## Stage 4: профиль, вес и резервные копии

Версия 0.4.0 добавляет профиль пользователя, оценочную дневную калорийность, журнал измерений веса и экспорт/импорт резервной копии в JSON. На главном экране доступны кнопки «Профиль», «Вес» и «Резервная копия».

**Важно:** расчёт калорийности ориентировочный. Для пользователей младше 18 лет его не следует использовать как жёсткий лимит похудения. Импорт резервной копии заменяет существующие записи дневника, профиль и историю веса.

В текущей среде не было Android SDK и Gradle, поэтому APK не собран, а Kotlin-компиляция ещё не подтверждена.


## Stage 5: стабилизация и автоматические проверки

- Добавлены автоматические тесты FastAPI: проверка состояния, поиск продуктов, валидация фотографий, обработка отсутствующего ключа, генерация рецептов и проверка меню на семь дней.
- Восстановление дневника из резервной копии выполняется одной транзакцией Room, чтобы не оставить базу частично заменённой при ошибке вставки.
- Добавлен GitHub Actions workflow: запускает тесты backend и собирает debug APK; APK публикуется как артефакт запуска workflow.
- Для локального запуска тестов: `pip install -r backend/requirements-dev.txt`, затем из папки `backend` выполнить `pytest -q`.
- Для реальной сборки Android APK нужен Android SDK; локально можно собрать из папки `android` командой `gradle assembleDebug`, если Gradle и Android SDK установлены.

В текущей среде Kotlin/Android сборка всё ещё не выполнялась: workflow можно запустить после загрузки проекта в GitHub. Наличие workflow не означает, что APK уже собран.


### Как получить APK через GitHub Actions

1. Распакуй архив и открой папку `nutriai_starter`.
2. Создай пустой репозиторий GitHub и загрузи **содержимое этой папки**, включая скрытую папку `.github`, в корень репозитория.
3. Открой вкладку Actions и дождись завершения `NutriAI checks`.
4. В успешном запуске скачай артефакт `nutriai-debug-apk`; внутри будет `app-debug.apk`.

Workflow собирает debug APK, он предназначен для тестирования и установки вручную, не для публикации в Google Play.


## Stage 6: подготовка к проверяемой сборке APK

- В workflow добавлен ручной запуск через `workflow_dispatch`, чтобы можно было запустить сборку из GitHub Actions по требованию.
- Указаны минимальные права `contents: read`, ограниченный срок хранения APK и сохранение отчётов Android-сборки при ошибке.
- Версия Android-приложения повышена до `0.6.0` (versionCode 6).
- Ключ Gemini теперь отправляется в заголовке `x-goog-api-key`, а не в query-параметре URL, чтобы снизить риск случайной утечки через журналы URL.
- Добавлены регрессионные тесты для передачи ключа и проверки неожиданного ответа генератора рецептов.
- Инструкция по получению APK вынесена в `BUILD_APK.md`.

**Статус:** backend-тесты можно запустить локально командой `pytest -q` из `backend`. Android APK в этой среде не собирался: отсутствуют Android SDK и Gradle, а для загрузки зависимостей нужен доступ к сети. Сборка через GitHub Actions станет подтверждённой только после успешного запуска workflow в твоём репозитории.


## Stage 7: сборочный процесс и документация

- Исправлен порядок команд в GitHub Actions: лицензии Android SDK принимаются до установки платформы и build-tools.
- Обновлена версия приложения до `0.6.0` (versionCode 6).
- Сборка APK всё ещё требует запуска GitHub Actions или Android Studio; в этой среде Android SDK и Gradle недоступны, поэтому успешная Kotlin-компиляция не подтверждена.

## Stage 9 — стабилизация ответов API и сборки

- Серверный режим `NUTRIAI_ENV=production` требует `API_ACCESS_TOKEN`; если токен забыли задать, защищённые маршруты не открываются. `/health` оставлен доступным для проверки состояния.
- Входные продукты нормализуются, дубликаты удаляются, некорректные строки отклоняются.
- Ответы ИИ для рецептов и недельного меню валидируются перед выдачей Android-клиенту.
- GitHub Actions запускает backend-тесты, Android unit tests, `lintDebug`, `assembleDebug` и проверку собранного APK.
- Backend-тесты: 23/23 пройдены локально. Android-сборка в текущем контейнере не запускалась из-за отсутствия Android SDK и Gradle; подтвердить APK можно только успешным запуском workflow.
