# NutriAI Stage 9 — проверка ответов ИИ и сборочного контура

## Изменения

- Сервер в `NUTRIAI_ENV=production` теперь отказывает в доступе к API с кодом 503, если `API_ACCESS_TOKEN` забыли настроить; `/health` остаётся доступным для health-check.
- Входные названия продуктов очищаются от пробелов, дубликаты убираются без учёта регистра; пустые названия и слишком длинные значения отклоняются.
- Предпочтения рецептов очищаются и не могут быть пустыми.
- Ответ генератора рецептов проверяется до передачи клиенту: структура рецепта, ингредиенты, шаги и неотрицательные числовые значения.
- Ответ недельного меню должен содержать ровно 7 дней, каждый день должен иметь список блюд, значения питания должны быть неотрицательными, список покупок — списком.
- GitHub Actions запускает Android unit tests, Android lint и сборку APK, затем проверяет APK через `aapt`.
- Версия Android-приложения повышена до 0.8.0 (versionCode 8), версия FastAPI — до 0.4.0.
- Добавлены 6 регрессионных тестов для production-конфигурации, очистки продуктов и валидации ответов ИИ.

## Проверки, выполненные локально

- `pytest backend/tests -q`: 23 теста пройдены.
- `python -m compileall -q backend/app backend/tests`: пройдено.
- XML Manifest и workflow проверены статически.

## Не подтверждено

В текущем контейнере нет Gradle и Android SDK, поэтому реальная компиляция Kotlin, Android lint и сборка APK не выполнялись локально. Workflow настроен на запуск этих проверок в GitHub Actions, но результат будет подтверждён только после его успешного выполнения в репозитории.
